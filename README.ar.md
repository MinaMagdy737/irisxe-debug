# بناء تعريف التشخيص من Windows عبر GitHub Actions

هذه وصفة بناء محليًا، لم تُرفع إلى GitHub ولم تُشغّل بعد. لا تحتوي على EFI أو سجلات الجهاز أو معرفات SMBIOS. الناتج المتوقع تعريف WhateverXe معدل للتسجيل فقط؛ نجاح البناء لا يعني إصلاح الشاشة.

1. أنشئ مستودعًا جديدًا في حسابك على GitHub. يمكن جعله خاصًا؛ تشغيل Actions في المستودعات الخاصة يخضع لحصة الحساب وحد الإنفاق، وقد يتوقف إن لم تتوفر حصة.
2. ارفع محتويات هذا المجلد إلى جذر المستودع، مع الحفاظ على المسار `.github/workflows/build-edp.yml`. الملفات المطلوبة: workflow و`edp-trace.patch` و`inputs.json` و`verify-inputs.py` وLICENSE.txt.
3. افتح Actions ثم `Build Iris Xe diagnostic kext` ثم Run workflow. التشغيل يدوي فقط؛ رفع الملفات وحده لا يبدأ البناء.
4. بعد النجاح، حمّل artifact المسمى `IrisXe-eDP-diagnostic-build`. يحتوي على kext ونتائج فحص مكدس الإقلاع وقيم SHA256. راجعها قبل تجربة التعريف في EFI منفصلة.

الوصفة تجلب المصدر والتبعيات المثبتة مباشرة من المشاريع العامة، وتتحقق من بصمات الملفات قبل التعديل وبعده، ثم تستخدم سكربت البناء الأصلي الذي يفحص مكدس الإقلاع والواردات غير المناسبة للنواة. لا تحتاج مفاتيح سرية أو Apple ID.

لا تُرفع حزمة مشروع Hackintosh الكاملة أو شجرة IORegistry. الحزمة المسموح بنقلها هنا هي ملفات وصفة البناء الستة فقط. لا يتم نشر إصدار أو فتح مشكلة للمطور بواسطة هذا workflow.
